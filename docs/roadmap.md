# Pathwise — Roadmap

This roadmap captures the MVP scope, later-phase plans, and the concrete
go-to-market / next-steps commitments from the pitch deck. It's a planning
document, not a build spec — no application code exists yet (see repository
status in the README).

## MVP (Phase 1)

The MVP is scoped to prove the core "why this route?" experience for a single
metro, without the breadth of a full product suite. In scope:

- Address search (origin)
- Destination search
- Walking and public-transit route generation
- Time-of-day selection for a given route
- Route considerations (the underlying factors behind a route's read)
- At least one alternative route suggestion per query
- Plain-language explanation of the factors behind the read ("why this
  route?")
- Save and share a route report

Explicitly deferred out of the MVP:

- A "live companion" mode (real-time, in-progress trip monitoring)
- Social features (sharing to a feed, following other users, etc.)
- Nationwide coverage — MVP is intentionally limited to one pilot metro

## Phase 2

Once the MVP validates core usage and willingness to pay in the pilot metro:

- Launch the full four-product lineup beyond the core Go experience:
  **Pathwise Stay** (hotel/travel), **Pathwise Home** (homebuyer/neighborhood
  reports), and **Pathwise Commute** (home-to-office mobility).
- Introduce personalization controls (weighting of crossings, infrastructure,
  activity level, historical incidents, route length, transfers) and family
  mode.
- Expand from one pilot metro to additional metros, prioritized by data
  availability (transit and pedestrian infrastructure data quality) and
  target-audience density.
- Stand up the Pathwise Plus subscription (~$7.99/month) and one-time
  Home/Moving reports as real, billed products.

## Phase 3

Once consumer usage and the intelligence engine are proven:

- Build out the B2B line: realtor subscriptions, hotel/hospitality
  integrations, corporate relocation packages, and an API / white-label
  offering for other platforms to embed Pathwise's route intelligence.
- Begin compounding the proprietary dataset described as "the moat" — user
  preferences, route comparisons, infrastructure context, time-dependent
  patterns, and data-quality signals — into increasingly city-specific route
  intelligence.
- Evaluate the longer-term "infrastructure" opportunity: licensing the
  Pathwise Intelligence Engine itself to other products (travel, real
  estate, mobility) rather than only shipping first-party apps.

## Go-To-Market

- Launch in a single metro rather than nationally. **Potential pilot:
  Dallas–Fort Worth.**
- Target initial audiences: homebuyers, families, travelers, commuters, and
  women traveling alone — groups with the clearest, most immediate need for
  journey-level context.
- Prove repeat usage and willingness to pay in the pilot metro before
  expanding geography or audience.

## Next Steps (from deck, Slide 17)

Concrete, sequenced next actions:

1. **Validate name, domain, and trademarks** for "Pathwise" before any
   further public-facing investment.
2. **Design 10–12 core screens** covering the primary MVP flows (address/
   destination entry, route report, "why this route?" explanation,
   alternative routes, save/share).
3. **Pick mapping and data providers** — base routing/mapping API, transit
   data source(s), and pedestrian infrastructure data source(s) for the
   pilot metro.
4. **Build a Dallas–Fort Worth pilot prototype** covering the MVP scope
   above.
5. **Test with homebuyers and travelers** — the two audiences with the
   clearest near-term use cases (Pathwise Home and Pathwise Stay) — to
   validate the core value proposition.
6. **Measure conversion** — specifically repeat usage and willingness to pay
   (free → Pathwise Plus, or one-time Home/Moving report purchases).
7. **Develop the B2B/API offering** once consumer traction is demonstrated,
   starting with realtor and hospitality partnerships.
